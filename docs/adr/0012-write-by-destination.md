# 0012 · 写入按目的地分级

- 状态：accepted
- 日期：2026-11-25
- 相关：0002（单一事实来源）、0009（项目库快照）

## 背景

此前「Agent 能不能写」被当成一个开关：默认关闭，需要时一次性开放。这个模型有两个问题：

1. **它把日常动作也拦住了。** 记一条灵感、生成一份草稿、更新水位——这些都写在本机自有库里，不产生任何对外后果，却和「往项目仓库塞文件」同属一个权限。
2. **它把风险算错了对象。** 风险不在「改了多少内容」，而在「影响了谁、能不能撤回」。

## 决定

写入按**目的地**分级，而不是按「是否写入」分级：

```
自有目录（配置根下）   默认允许，不打扰
项目目录（被观察仓库） 默认禁止；要写就一次一申请
对外发送（网络）       发出即不可逆，单独确认
删除                   横切动作，永远逐次确认
```

需要确认时，由评估器（LLM）按三个轴给出风险，并把判据露出来：

```
影响面        本机级 / 项目级 / 跨项目
可逆性        可逆 / 需重建 / 不可逆
是否离开本机   否 / 是
```

规则：

- 评估不可用或超时，**一律按高风险**处理，并写明失败原因。
- 人可否决评级；改判不覆盖原判据，而是并列追加一条人工记录。
- 「低风险以后不用再问」只作用于低风险，不放开高风险。
- 项目目录的授权与会话绑定，换会话重置。

## 后果

- **好的**：写不再稀缺，Agent 可以正常维护自己的库；保护集中在真正会影响别人的地方。
- **好的**：风险分级有判据，人能判断「它是不是偷懒」。
- **代价**：配置与文档必须说清「默认能写，但只能写自己的」，否则会被误读成「默认关闭」。
- **代价**：项目目录授权按会话，会让长期维护同一项目的文档每天点几次；若实际频繁，可改成按项目记忆，但**写入清单仍每次显示**。
- **代价**：评估器有成本与延迟；高风险确认会多一次模型调用。
