# 三种界面形态按入口分工，不做模式切换

**Status: superseded by ADR-0005.** 用户在实际试用后要求三种形态合并在同一个客户端窗口内自由切换，因此本文结论作废，保留作为决策历史。

原型验证了三种结构不同的界面：单一下一步（A）、待办收件箱（B）、对话即界面（C）。三者都保留，但各自绑定一个入口，而不是在同一个窗口里提供模式开关：A 给桌宠，B 给面板，C 给独立会话窗口（与 Telegram 同构）。

理由：三种形态对应三种注意力状态——余光可见时只能承载一件事，坐下来处理时才适合逐条过，在外面只能用一句话问。若把三者做成同一个面板里的模式，用户每次打开都要先回答「我在哪个模式」，这恰好是这次要消除的「SOP 不明确」。

## Consequences

- 每个入口独立演进，改动一个形态不会牵动另外两个。
- 新增入口时必须先回答它属于哪种注意力状态，不能顺手再加一种布局。
- C 与 Telegram 共享同一套卡片语义，避免两处各自发明展示方式。
- 代价：同一份数据在三个入口有三种呈现，状态同步依赖各自的快照拉取，不做跨窗口广播。
