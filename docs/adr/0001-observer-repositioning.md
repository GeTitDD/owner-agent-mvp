# 产品定位收窄为只读观察员，写链路降级为默认关闭

仓库里已经有一条完整的审批写入链路（code-write Job → worktree 提案 → 二次审批 → 沙箱 → 单轮修复），由 10 个测试文件支撑。新定位把产品叙事改为「多项目非侵入式观察员」，写链路保留在同一代码库内但由 `writeMode: off` 默认关闭。这样做的原因是：观察员的卖点是「不碰你的仓库」，而写入能力是这个卖点的反例；两者不能同时出现在主叙事里，但删除写入链路会连同已验证的 hash 审批与容器复核模型一起丢掉。

## Consequences

- 手机端不再提供审批按钮：飞书机器人只发不收，审批必须回到 Windows 桌面端。这与 `writeMode` 默认关闭一致——需要点的场景本来就少。
- 记忆与审计分家后，存储长期是两套：Markdown 树存人读的东西，SQLite 存机器查的东西，不存在「全部迁移」意义上的单一存储。
- 观察台押在 Electron 客户端上，而该层目前没有单测、有渲染进程崩溃记录；v0.1 的验收依赖它，需要先补最小冒烟测试。观察台改为 Web 优先后，这条风险降级（见 ADR-0003）。
