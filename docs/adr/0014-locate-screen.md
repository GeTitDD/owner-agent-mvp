# 0014 — 定位屏取代全局聚合，未读与水位分离

- 状态：accepted
- 日期：2026-11-26
- 相关：0011（单入口卡片）、0002（单一事实来源）、0012（写入按目的地）、GLOSSARY「定位屏 / 关注顺序 / 标记已读」

## 背景

产品的目的是降低多项目开发的认知负担。现在的全局模式是一个只读聚合：列出各项目条目数、最近变化与跨项目共用，
但没有排序理由，也没有把「未读」放在用户第一眼能看到的地方。用户要先知道「先看哪个」，才能开始定位。

同时存在一个会自我破坏的机制：水位在**进入项目**时推进（旧口径）。如果定位屏上点一行项目就等于切换，
那么依次浏览几行，未读就会全部清零，定位屏的排序在浏览过程中自己塌掉。

## 决定

1. **定位屏替换全局聚合**：不选项目时，主内容是按关注顺序排列的项目列表，不是聚合数字。
   每行四段（项目名、待确认候选数、三类未读、上次看过）+ 一行最近决策。
2. **关注顺序是算出来的**，不是维护一份清单：
   `有待确认候选 > 有未读变化 > 超过 7 天未看 > 其余`；手动置顶只在同级内改顺序。
3. **只把记忆候选算作「待确认」**：Idea→Lesson、Lesson→Knowledge、Decision。
   写入/外发/删除的动作级确认不计入，避免一次写入让排序抖动。
4. **未读与水位分离**：切换项目不清零；清零只有两个明确动作——
   打开 `/变化` 看完，或行内「标记已读」。
5. 陈旧阈值固定 7 天，不做配置项。

## 后果

- **好**：进入客户端第一眼就能回答「先看哪个」，且理由在行内容里可见；
- **好**：浏览定位屏不会破坏排序，未读的语义变成「还没看内容」而不是「还没点过」；
- **好**：动作级确认与记忆候选分开，排序不受临时卡片影响；
- **坏**：需要改水位推进的时机——`/变化` 之外不再自动推进，旧行为要迁移；
- **坏**：全局聚合不再是一个独立概念，原先依赖它的入口要重新指向定位屏；
- **坏**：灵感收件箱的列表视图停做（#94/#96/#97），只保留捕获与「回执上提升」；
- **不变**：写入四档、只读工具面、同步冲突交人都不受影响。

## 备选方案

- **保留聚合、另开一个定位入口**：多一个入口要维护，且与单入口卡片冲突；
- **进入项目即清零**：实现最省事，但定位屏在浏览时自我塌陷；
- **把动作确认也算待确认**：排序会随每次写入抖动，且「待确认」的含义被稀释；
- **让用户维护关注清单**：清单本身成为新的认知负担，且与「关注顺序是算出来的」冲突。
