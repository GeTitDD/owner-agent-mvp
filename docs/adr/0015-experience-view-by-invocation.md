# 0015 — 经验的查看走调用与隐式检索，卡片壳不设浏览界面

- 状态：accepted
- 日期：2026-11-26
- 相关：0011（单入口卡片）、0014（定位屏）、`docs/DIRECTION.md`「经验的查看」

## 背景

经验链要补入口（Idea → Lesson → Knowledge），很容易顺手在卡片壳里加一个「经验库 / 详情页 / 收件箱」。
但卡片壳的约束是单入口：每加一个浏览界面，就多一处需要维护的列表、筛选与状态；
而「查看经验」是低频、深度阅读的动作，不是每天 60 秒定位的一部分。

完整工作台（`npm run workbench`）本来就是为系统性浏览准备的：它只绑 loopback，能列知识、看修订与证据。

## 决定

1. **卡片壳不设独立的经验库、详情页或收件箱**。
2. 查看只走两种方式：
   - **显式调用**：`/经验 <关键词>`，在对话流里返回匹配的 Lesson / Knowledge（摘要 + 命中理由）；
     没有关键词时只给计数与最近几条，不做列表页。
   - **隐式查看**：提问时按项目与领域检索相关经验，作为只读依据带进这一轮（引用块），
     不自动写入任何项目记忆。
3. 候选的确认仍在流内完成（两次 HITL）；确认卡是对话的一部分，不算浏览界面。
4. **完整工作台承担浏览**：按状态筛选、看修订、看证据。Lesson 的浏览/证据视图在工作台补，
   不搬回卡片壳。

## 后果

- **好**：卡片壳保持「一个输入框」，不出现第四个界面；
- **好**：显式命令覆盖「我想看看这类经验」，隐式检索覆盖「回答时顺手用到」；
- **好**：深度阅读回到本来就为它准备的工作台，筛选与修订视图不用做两遍；
- **坏**：用户必须记住一个命令，或知道工作台的存在；需要在 `/` 面板里列出该命令；
- **坏**：工作台目前只列 personal units 与静态知识，Lesson 浏览需要补一张票；
- **不变**：经验链的数据模型、状态与两次确认都不受影响。

## 备选方案

- **在卡片壳里做知识页**：与单入口卡片冲突，且要维护列表/筛选/详情三套界面；
- **只做隐式查看**：用户无法主动问「我有哪些关于重试的经验」；
- **只靠工作台**：为了看一眼经验离开当前对话，切换成本高于收益；
- **把候选确认也搬到工作台**：确认是高频动作，离开对话会让 HITL 变成排队。
