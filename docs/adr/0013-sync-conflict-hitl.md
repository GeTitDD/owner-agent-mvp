# 0013 · 多端同步走私有仓库，冲突交人

- 状态：accepted
- 日期：2026-11-25
- 相关：0002（单一事实来源）、0007（三层沉淀）、0009（项目库快照）

## 背景

同一套记忆会在多台机器上产生：办公机、家里、笔记本。没有同步时，两边各自生长，无法合并；做同步时，又要回答「哪边说了算」。

而「哪边说了算」这个问题，往往在真正冲突的那一次才需要回答，平时回答它只会增加规则。

## 决定

用**一个私有 GitHub 仓库**承载文档，本机保留可离线使用的副本。同步不宣告谁是权威，只规定流程与冲突处理：

- 单位是**文档**（含 frontmatter：项目、类型、状态、版本），不是整棵树。
- 顺序固定：**先拉，再推**。不先拉就推，等于拿旧副本覆盖。
- 两边改了同一篇 → **停在冲突确认，不自动合并**。
- 冲突由人四选一：远端覆盖本地 / 本地覆盖远端 / 两段都留着 / 跳过。
- 「跳过」只跳过这一篇，其余照常推送，并在本地留下「未解决」标记。
- 远端删除采用**归档**，不做真删。
- 凭证从环境变量读，不写入配置文件。

## 后果

- **好的**：不需要在平时维护一套权威规则；只有真冲突时才问一次。
- **好的**：文档是 markdown + git，天然可 diff、可回溯、可迁移。
- **好的**：离线仍可读写，联网后补同步。
- **代价**：必须显示「未同步」状态，否则用户会以为已经存好了。
- **代价**：冲突处理是常态路径而非异常路径，界面上必须做得像「一次选择」而不是「一次报错」。
- **代价**：私有仓库要求 GitHub 账号与 token；完全离线的用户等于只用本机，文档要写清楚而不是假装支持。
- **不做**：反向同步（远端被手改后自动回灌）、多目标镜像（Notion / 飞书文档）、团队权限模型。
