# 0011 · 单入口卡片

- 状态：accepted
- 日期：2026-11-25
- 取代：0004（三种界面）、0005（面板分档）、0006（专注 / 知识 / 对话三档）

## 背景

客户端从「桌宠 + 独立面板」演化到「三档面板 + 两区（操作区 / 工作区）」。每一档都在解决一个真实问题，但叠加的结果是：

- 用户先要判断「这件事在哪一档」，再判断「在哪一块」——两次定位成本。
- 每加一个能力就要新增一个入口或一块区域，入口只会越来越多。
- 待办与项目记忆争夺首屏，两边的信息密度都不够。

## 决定

客户端收敛为**一个窗口、一个入口**：顶栏 + 对话流 + 输入框。

- 顶栏只承载全局状态：会话、当前项目（可为空，空即全局）、写范围、监控、导出、配置。
- 能力通过两种语法进入：`/` 调用技能（不带对象），`@@` 处理对象（先指认再动作）。
- 其余能力不占入口：要么是某条消息、某个卡片的悬停动作，要么是块内的声明式按钮。

## 后果

- **好的**：只有一条心智路径——「说，或者打 / 或 @@」。新增能力不再需要新增入口，只需要新增一个技能或一个 `@@` 方法。
- **好的**：项目记忆（ADR-0008）回到首屏，不再与待办分地盘。
- **代价**：深度功能（版本浏览、删除项目、配置）都多一次点击。可以接受，因为它们不是高频动作。
- **代价**：面板层需要重做，旧的档位与分区代码成为死代码，需要在迁移中删掉而不是保留开关。
- **代价**：`/` 与 `@@` 的划分必须被解释清楚，否则用户会问「为什么这个要两个 @」。划分标准写在 0014（待写）。
