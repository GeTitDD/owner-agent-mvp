# 主路径从待办审批改为项目记忆：变化窗口与决策

产品一直按「观察 → 待办 → 审批 → 补丁 → 沙箱 → 合并」这条链叙事，但真实数据说明它没被使用：真实库里 0 条补丁、0 次沙箱运行、0 个任务、0 条事件，只有一个 queued 任务躺了两周。与此同时，使用者说出来的痛点是另外两件事：随时知道项目变了什么，以及想起当时为什么那么定。前者是状态感知，后者是决策记忆，两者都不在原来的主链上。

所以把主路径换成「变化窗口 + 决策」，写链路保留但移出主界面：它仍是唯一能「让 AI 改代码而人保留否决权」的机制，删了将来要重建；但当主入口就是自我欺骗，因为数据已经说明不会用。

- **变化窗口**：每个项目记一个「上次查看」水位，进度就是水位之后的新提交、未提交改动与观察员事件。进入项目详情时先算出差异给人看，再把水位推到当前——先推进后计算等于让人白开一次。
- **决策**：知识的一种，分改动意图与放弃的方案，状态是生效中、已被取代、已放弃。来源是其他 Agent 的会话与提交信息；系统提议，人在项目详情卡里确认后才入库。放弃的方案靠对话里「不做了、换掉了、算了」这类表达识别，删除类提交只作线索——`git` 能说明哪些行没了，说不出为什么。
- **外部会话**：先接 Codex 与 Claude Code 两个 JSONL 源，按 cwd 精确匹配项目 root，匹配不到就丢弃并计数，不猜。只提炼决策，不做全文存档：全文检索是另一个产品，而且 OpenCode 那 5.5 GB 的会话库存进本地库并不划算。
- **状态机按种类分派**：同一张知识表里，规则用待验证 / 已验证，决策用生效中 / 已被取代 / 已放弃。一个决策不会「被验证」，它只会被后来的决定取代。

脱敏是已知的薄弱环节：全读会话原文再加正则脱敏，一定会漏（base64 里的密钥、被截断的 token）。缓解手段是入库前显示「本次脱敏 N 处」，让人能从数字上看出异常，而不是假装安全。

## Consequences

- 待办审批、补丁、沙箱从主界面移出。它们的代码与测试保留，作为隐藏能力，将来真要交办时不必重建。
- 需要新的持久化：每项目的水位、决策条目与它的证据引用（会话 id 加位置，或提交 sha）。
- 知识表需要按 `kind` 分派合法状态，否则「生效中的知识」和「已验证的知识」会互相冒充。
- 外部会话摄入是新增的外部依赖面：Codex 与 Claude Code 的文件布局一变，摄入器就要跟着改，所以匹配失败必须显式计数而不是静默跳过。
- 「跟上进度」从此依赖 git 探针的准确性；探针读不到仓库时，变化窗口应当说明原因，而不是显示「没有变化」。
