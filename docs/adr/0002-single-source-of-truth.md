# 同一条事实只存一处，另一处只存指针

> 2026-11-27 实现核对：单一事实归属原则仍有效，但下文将人工记忆固定归属 Markdown 的表示分工与当前实现不一致。
> 当前个人知识工作台在 SQLite 保存本机记忆和修订，Markdown 是显式同步的文档投影；这不是「远端永远覆盖本机」。
> 本文原始背景保留供追溯，不能作为当前落盘位置的操作指南；表示分工的待议修订见
> [ADR-0016 草案](0016-local-memory-representation.md)。本次没有迁移数据或改变同步冲突政策。

记忆（Markdown 树）与审计（SQLite）分家后，同一件事很容易两边各写一份，最终给出两个互相矛盾的答案——比如观察台显示「停滞 5 天」，`brief.md` 里却写着「上周更新过架构」。因此约定：**事实的归属按「谁需要读」划分，归属方存内容，另一方只存指针。**

- 机器要查、要 join、要统计的 → SQLite 存内容（job 状态、事件、投递记录）
- 人要读、要 diff、要回滚的 → Markdown 存内容（画像、决策、经验、风险结论）
- 跨界的部分只写引用，例如 `brief.md` 里写 `recent_activity: see owner.sqlite#project/<id>`，不写「最后一次提交是 3 天前」

## Consequences

- 记忆文档不再能脱离数据库独立阅读，这是有意的取舍：宁可少读一行，也不要读到一个过期数字。
- 观察台渲染时需要一次现查，不能只读文件树；这个查询必须在 HTTP 层有测试。
- 迁移脚本要遵守这条规则，否则会把「两套答案」原样搬进新结构。
