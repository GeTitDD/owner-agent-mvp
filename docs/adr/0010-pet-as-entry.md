# 客户端以桌宠为入口，面板降为下钻

现在的客户端是「桌宠 + 独立面板」：桌宠是个会动的按钮，点开另一个 520×780 的窗口，所有事都在那里发生。这套结构的后果是**要么不看，要么全看**——桌宠只有「有/没有」两态，无法承载「一眼扫过」。

改成三层形态，同一个产品的三种尺寸：

```text
桌宠        一个表情加一个数字徽章        常驻，最小
卡片        一条内容加一个主操作          单击就地展开，同一容器变高
宽窗        左侧三档 + 右内容            深入时才打开
```

三条规则支撑这套结构：

- **桌宠自己承载内容，不只是跳转。** 单击是展开而非打开新窗口；气泡与卡片是同一个容器的高度变化，避免桌面上同时挂两个浮层。破坏性动作（批准、拒绝、删除）一律不进卡片——卡片空间小，误触不可逆，而宽窗里有上下文和确认。
- **展开方向自动朝屏幕中心。** 桌宠通常停在屏幕角落，往角落方向展开会有一半飘出屏幕。这是手机「拇指区」在桌面上的等价物，且必须自动：让用户去想「该往哪边拖」就是设计失败。
- **动即通知。** 动画只在三种情况下发生：有新变化、有人在等你、正在跑。静止是默认。此前动画一直在播，结果是动作不再传递任何信息——用户学会无视它，就像无视一个永远在转的加载图标。

## 三档的迁移

原来的三档（专注 / 知识 / 对话）是「面板为主」时代的产物。在桌宠为入口的结构下换成三档：**变化 / 项目 / 记**。

- **变化**：每个项目一行，回答「哪个项目动了」。不列单条提交，否则它会退化成 git log。
- **项目**：左列表加右详情，详情即项目库（画像、图谱、经验、知识、发布）。
- **记**：灵感收件箱与待确认候选。它是沉淀的入口，也是桌宠在桌面上的独有价值——桌面上你不会打开编辑器，所以记录必须比打开编辑器更快。

「待办」作为一个独立入口消失。审核候选归入「记」，审批写入降为项目里的次要入口。理由在 ADR-0008 里已经写过：真实库里补丁 0、沙箱 0、审批从未打开，把执行路径放在第一位与使用事实相反。

## Consequences

- 全局快捷键承担「任何地方记录」：手机上靠分享面板，桌面上等价物是随时可唤起的单行输入，外加把文件拖到桌宠身上。
- 全屏应用时自动隐藏，托盘保留图标。桌宠最容易被卸载的原因是「它碍事」，自动隐藏比让用户手动关更不容易被记恨。
- 桌宠位置要记住，并在显示器变化时回落到主屏。当前的绝对坐标在换显示器后会飘到不存在的屏幕上，这是 bug，不是设计问题。
- 宽窗保持横向，项目档用两栏。这与「一屏一件事」并不冲突：一屏一件事约束的是卡片那一层，宽窗本来就是给结构留的。
- 卡片只能展示一条。取哪一条用固定优先级：有新变化的项目 > 待确认的知识候选 > 最近一条灵感。让用户手动钉住会引入维护成本，而桌宠的价值正是「不用维护」。
