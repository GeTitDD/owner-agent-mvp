# 客户端三种模式：专注、知识、对话

面板只保留三个模式，各自回答一个问题：专注回答「现在要处理什么、这个项目是什么样」，知识回答「我已经沉淀了什么」，对话回答「这件事为什么是这样」。

- **专注**：跨项目的待办（按项目分组，首个展开其余折叠）+ 所选项目的只读详情（画像、图谱、想法、Playbook 等九块，内部分段折叠）。知识、测试、补丁、运行只在详情里放入口与计数，不重复渲染内容。
- **知识**：只读浏览本地 SQLite 里的候选、已验证知识与经验，按类型分组、按项目筛选，并可直接审核候选；技能把域包、pstack、插件三处合并成一个只读列表，点开看路径与描述。
- **对话**：Pi SDK 会话，绑定项目，只能读文件（read/grep/find/ls），只回答不改代码；要改必须打开「交办」开关，走既有的审批链路。会话持久化到 SQLite，自动命名可重命名。

同时取消「当前项目」这一全局状态：专注卡默认看第一个项目、刷新不记忆，交办与新建会话时显式选择项目。这样避免出现「界面上显示 A 项目、实际在改 B 项目」的错位。

## Consequences

- 交办和新建会话都必须多一次选择；换来的是不会误操作到错误项目。
- 详情里九块内容会有重复入口（知识、测试、补丁），点击跳转到对应模式或详情，不复制内容。
- 对话权限被收窄为只读，回答「这个文件为什么这么写」这类问题仍然可以，但不能在对话里直接改。
- 知识模式第一版只覆盖 SQLite 一份数据；`owner.json` 里的项目知识（Telegram 那份）暂不进入，避免同屏两套不同步的内容。
