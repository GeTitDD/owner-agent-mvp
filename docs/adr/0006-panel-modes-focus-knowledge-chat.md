# 客户端三种模式：专注、知识、对话

面板只保留三个模式，各自回答一个问题：专注回答「现在要处理什么、这个项目是什么样」，知识回答「我已经沉淀了什么」，对话回答「这件事为什么是这样」。

- **专注**：跨项目的待办（按项目分组，首个展开其余折叠）+ 所选项目的只读详情（画像、图谱、想法、Playbook 等九块，内部分段折叠）。知识、测试、补丁、运行只在详情里放入口与计数，不重复渲染内容。

> 后续修订（#69 / #72）：只读详情卡已删除，四个计数并入工作区；专注页改为「操作区 + 工作区」两区。上面这句里的「只读详情 / 九块 / 详情里放入口」已被取代，保留原文只为记录当时的决定，详见文末「修订」。
- **知识**：只读浏览本地 SQLite 里的候选、已验证知识与经验，按类型分组、按项目筛选，并可直接审核候选；技能把域包、pstack、插件三处合并成一个只读列表，点开看路径与描述。
- **对话**：Pi SDK 会话，绑定项目，只能读文件（read/grep/find/ls），只回答不改代码；要改必须打开「交办」开关，走既有的审批链路。会话持久化到 SQLite，自动命名可重命名。

同时取消「当前项目」这一全局状态：专注卡默认看第一个项目、刷新不记忆，交办与新建会话时显式选择项目。这样避免出现「界面上显示 A 项目、实际在改 B 项目」的错位。

## Consequences

- 交办和新建会话都必须多一次选择；换来的是不会误操作到错误项目。
- 详情里九块内容会有重复入口（知识、测试、补丁），点击跳转到对应模式或详情，不复制内容。
- 对话权限被收窄为只读，回答「这个文件为什么这么写」这类问题仍然可以，但不能在对话里直接改。
- 知识模式第一版只覆盖 SQLite 一份数据；`owner.json` 里的项目知识（Telegram 那份）暂不进入，避免同屏两套不同步的内容。

## 修订记录

- #38 曾写「不传项目标识时行为与现在完全一致」。该说法已被 #41「取消全局当前项目」取代：现在不传项目标识只表示「视图默认第一个项目」，交办与新建会话都必须显式选择项目，不再与旧行为一致。
- 视图项目（看哪个）与交办目标（改哪个）是两个独立状态：点详情卡的项目标签只换视图，不会顺带改交办目标；只有「交办到 …」菜单能设置交办目标。

## 修订

- **只读详情卡已删除，四个计数并入工作区**（#72）：`desktop/focus-detail.cjs` 与它的九块内容、`tests/focus-detail.test.mjs` 一并移除。原因是详情卡与真工作区重复：同一个项目的画像、图谱、想法、Playbook、待办在上下两块各画一遍，计数与入口也各取一份数据。现在知识 / 测试 / 补丁 / 运行四个计数留在工作区入口条里（见 `docs/UI_GUIDE.md` §5），点入口跳到它原来的位置。
- **专注页改为「操作区 + 工作区」两区**（#69 / #73）：上面操作区跨项目回答「现在要你处理什么」（待办 / 运行中 / 待提炼，加操作结果下钻），下面工作区常驻展开、永远绑定一个项目。项目切换只保留在工作区顶部（`#workProjectBar`），「添加项目」挂在切换行尾；设置向导搬进设置面板，不占工作区。
- **原因**：详情卡是中间层，既不是「现在要处理什么」，也不是「这个项目是什么样」；它与工作区重复，且切换标签与工作区数据来自不同快照，容易让读者以为在看两个项目。判断依据仍是上文「取消全局当前项目」与「视图 / 交办两个独立状态」，没有改变。
