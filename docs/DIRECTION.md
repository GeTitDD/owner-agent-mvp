# 方向对齐：降低多项目开发的认知负担

- 状态：已对齐（2026-11-26）
- 依据：本轮 grilling 的三轮问答；术语已同步到 `GLOSSARY.md`；决定记录在 `docs/adr/0014-locate-screen.md`

## 目的

> 降低开发者在多项目开发与跟踪过程中的认知负担，同时管理多项目沉淀经验。

这句话拆成两个可验收的目标：

1. **定位**：重新进入一个项目，60 秒内能说出「上次到哪、为什么、下一步」。
2. **沉淀**：一条经验只存一处，并且能从它的项目走到跨项目复用，中间只经过两次人工确认。

「下一步」不生成建议，只显示「还有什么在等你判断」与「还有什么没看」——不把定位屏变成待办列表。

## 已定的基础取舍

| 问题 | 结论 |
| --- | --- |
| 首要负担 | 变化不知情 + 决策失忆；切换成本是症状，选择困难是副产品 |
| 「跟踪」 | 只读变化 + 关注顺序；不做任务管理、不接管外部 issue/PR |
| 经验原子 | Lesson（现象→原因→对策）；Idea 是前置候选，Knowledge/Decision 是升级形态 |
| 规模 | 单人、3–10 个项目、领域可混 |
| 验收 | 60 秒定位；「免重复解释」与「复用次数」为辅 |
| 写入范围 | 只写自有记忆库；项目仓库始终只读，要写回由人自己复制 |

## 定位屏

不选项目时的主内容，**替换**现在的全局聚合，不是第二个入口。
可点的 HTML 样稿：`docs/prototypes/locate-screen.html`（静态数据，只演示排序与已读）。

```text
项目名                待确认 2 · 未读 提交3/改动1/知识0        3 天前
最近决策：重试上限固定为 7 次，不再递归
```

- 每个项目四段 + 一行最近决策；
- 排序（关注顺序）：**待确认候选 > 有未读变化 > 超过 7 天未看 > 其余**；
  手动置顶只在同级内改顺序，理由必须能从行内容看出来；
- 「待确认」只算**记忆候选**（Idea→Lesson、Lesson→Knowledge、Decision），
  写入/外发/删除的动作级确认不计入，否则排序会随一次写入抖动；
- 未读清零只有两个明确动作：打开 `/变化` 看完，或行内「标记已读」；
  **切换项目不清零**——否则在定位屏上浏览几行，排序自己就塌了；
- 陈旧阈值固定 7 天，不做配置项。

## 经验链

```text
Idea（/记灵感，回执上可直接提升）
  └─(HITL 1)─▶ Lesson（现象 / 原因 / 对策，绑定项目）
        └─(HITL 2)─▶ Knowledge 或 Decision（选范围：项目 / 领域）
```

- 两次确认都发生在**当前项目的对话流里**，不建审核队列；
- 不提升的灵感留在记忆里靠搜索找到，**不做收件箱**；
- 提炼入口：项目内输入 `/提炼经验 [N]`（默认 5 条），只处理「已终态且未提炼」的执行记录；
  没有待提炼时明确回执，不调模型；
- Decision 候选来自显式命令 `/提炼决策`（扫当前项目的会话，产候选，逐条接受/改写/拒绝）；
  `/记决策` 保留为手动入口；不做后台常驻扫描；
- 跨项目：升级后的 Knowledge 作为正式依据；未升级的 Lesson 只在提问时作**只读参考**；
  永不自动写入另一个项目的记忆库。

## 旁路

- 发布/快照（版本、导出、飞书）保留，但不参与 60 秒定位，也不再为它加界面；
- 桌宠、监控、技能面板沿用现状，不因这次对齐扩张。

## 验收场景

三个项目：

```text
A  有 2 条待确认决策候选，30 分钟前有提交
B  只有未读变化（提交 3 / 未提交 1），昨天看过
C  7 天没碰，没有变化
```

从打开客户端到说出「先看 A 的哪两条决策」必须 < 60 秒：

1. 默认落在定位屏，A 排第一（候选优先），行内能看到两条候选的入口；
2. 点 A 进入项目，处理候选；返回后 A 的角标减少，B 仍在原位；
3. B 不点「标记已读」，它的未读不会因为进出 A 而清零；
4. C 排在最后（陈旧），但仍在列表里，不隐藏。

## 经验的查看

卡片壳**不设独立的经验库、详情页或收件箱**。查看只有两种方式：

- **显式调用**：`/经验 <关键词>` 在对话流里返回匹配的 Lesson / Knowledge（摘要 + 命中理由），
  不打开新页面；没有关键词时只给计数与最近几条，避免把对话流变成列表。
- **隐式查看**：提问时按项目与领域检索相关经验，作为只读依据带进这一轮（引用块），
  不自动写入任何项目记忆。

候选的确认仍在流内完成（Idea→Lesson、Lesson→Knowledge 两次 HITL），这不算「独立 UI」，
它就是对话里的一张卡。

需要系统性浏览、按状态筛选、看修订与证据时，去**完整工作台**：

```powershell
npm run workbench     # http://127.0.0.1:4317，仅本机
```

工作台已经能按项目与状态浏览 Lesson、查看机制 / 对策与证据；
卡片壳不复制这套浏览界面，只保留流内查看与确认（ADR-0015）。
