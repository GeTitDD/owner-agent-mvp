# v0.1 观察闭环

目标：用最小代价验证「多项目观察员」到底有没有用。**只做只读采集、事件提醒、观察台三件事**，不碰记忆迁移、问答与 Dreaming。

## 范围

| 做什么 | 不做什么 |
|---|---|
| 只读探针（git + 文件系统） | 进程/运行时探针 |
| 三类事件：停滞、漂移、积压 | CI 失败、依赖过期、审批超时 |
| 事件指纹 + 24h 冷却 | 事件历史回溯分析 |
| 每项目每日 1 条飞书聚合 | 飞书回执、按钮、双向交互 |
| Web 观察台（项目卡片 + 事件流） | 记忆树、迁移、问答、Dreaming |
| 桌面新增观察台页签（壳） | 改造现有面板与桌宠 |

## 架构增量

```
probe（纯函数）→ events（纯函数）→ 聚合器 → 投递（飞书）
                          ↓
                    SQLite 审计表
                          ↓
              Web 观察台（HTTP 路由，可测）
                          ↓
              Electron 页签（loadURL，仅壳）
```

两条硬规则：

1. **同一条事实只存一处**（ADR-0002）。事件与投递记录进 SQLite；`risks.md` 之类只写结论与指针。
2. **观察台是 Web 优先**（ADR-0003）。数据层必须是可单测的纯函数，Electron 只负责打开它。

## 任务与验收

| # | 任务 | 验收条件 | 依赖 |
|---|---|---|---|
| T1 | 探针：`ProjectSnapshot` 纯函数 | 给定 fixture 仓库，输出 HEAD/branch/落后提交数/未提交文件数/Manifest 摘要；单测覆盖 6 种仓库状态（干净、脏、无 remote、detached、空提交历史、多包） | — |
| T2 | 事件引擎 | 3 类事件按阈值触发；同指纹 24h 内只出一次；重启后从事件表恢复，不补发历史 | T1 |
| T3 | 审计表 | `observer_events` / `observer_deliveries` 两张表，含指纹唯一索引；同一事件重复写入不产生新行 | T2 |
| T4 | 聚合与投递 | 每项目每天 ≤1 条；22:00–08:00 不投递；飞书 webhook 失败重试 1 次并记录失败原因 | T3 |
| T5 | Web 观察台 | `GET /observer` 返回项目卡片与事件流；首屏渲染不含阻塞请求；有 HTTP 层测试 | T3 |
| T6 | 桌面页签 | 托盘菜单新增「观察台」，`loadURL` 指向 T5 的路由；Electron 崩溃不影响观察台独立访问 | T5 |
| T7 | 验收 | 用 2 周真实数据人工核对：10 秒内指出最危险项目；误报率 <20%；重启不重复推送 | T1–T6 |

约 6–8 个工作日，T1/T2 可并行，T5 可与 T4 并行。

## 风险

- **误报率可能超过 20%。** 阈值是第一版猜测，验收时若超标，先调阈值再考虑增加信号源，不要急着加事件类型。
- **飞书 webhook 是一次性配置。** URL 泄露等于任何人都能往你的群发消息，因此只存本地配置，不进仓库。
- **桌面页签可能拖慢验收。** 若 Electron 侧不稳定，T6 可整体砍掉，观察台用浏览器访问即可，不影响 v0.1 结论。
