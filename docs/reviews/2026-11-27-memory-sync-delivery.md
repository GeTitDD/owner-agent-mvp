# 第六批：真实记忆同步与失败恢复

日期：2026-11-27。整体目标继续进行，本批交付不代表全部功能完成。

## 用户旅程

配置 → 同步，填写自己的私有 GitHub 仓库与分支并保存；检查两侧完整清单，展开正文、范围与证据，
冲突逐篇选择远端 / 本机 / 两段都留 / 跳过；勾选确认后才应用接收/归档并推送。
清单支持查找和分批显示，未显示的条目不会从计划中丢弃；没有选择完不能执行。
两段都留标明来源，范围沿用本机，远端差异元数据保留在合并文本中；不能静默丢字段或截断正文。

未配置或缺凭据时显示「仅本机」，不沿用其他目标或旧验收的成功状态。
发现远端变化后，即使取消预览也不会继续显示「已同步」。本机新增变化退出完全同步状态。
跳过只影响该篇，其他篇照常传输；未解决标记跨重启保留。远端移除转为本机归档，可明确恢复。

检查中和传输中都有停止入口。过期预览、任一侧变化、并发推送都要求重新检查；不强推旧内容。
先接收或合并、后推送失败时，保留已应用内容并报告篇数，重试不重复合并或生成修订。
错误日常提示使用中文，Git / IPC 技术细节可展开；成功、未解决与部分失败不会混为绿色成功。
关闭设置或切换会话不清空原草稿，慢检查不会给另一个会话追加回执。

## 实际同步的数据与保护

- 活跃知识（含决策）和经验、所需证据，使用稳定身份完整枚举，不受 UI 的 500/1000 条上限影响。
- 本机 SQLite 继续持有当前事实；Git 中的可读 Markdown 是带版本校验的传输投影。
- 不上传整份数据库、应用配置、凭据、原始聊天、执行审计和被观察项目文件。画像、图谱、快照和域定义不在当前范围。
- 结构化机器路径省略或转换为稳定引用；正文与证据摘录保持原文，确认前可展开核对。
- 保留项目 ID，未在本机登记时明确提示；不猜测目录、不自动改归属或登记项目根路径。
- 私有性、当前用户所有权和推送权限通过固定 GitHub 接口验证。凭据只来自环境变量，既不回传窗口，也不写配置或 Git 缓存。
- 使用 app 自有 bare 缓存，不检出远端文件；不继承外部 Git 配置/索引/跟踪环境，不允许符号链接、路径穿越或强推。
- 单篇 1 MiB、完整清单 10000 篇 / 64 MiB；按发布后的完整树校验，超限明确停止，不截断。
- 归档不真删内容或修订，也不参与当前项目检索、经验去重、决策列表；旧卡片不能静默修改归档内容。

## 仍未覆盖与后续

环境为 macOS、Node 22.23.3、仓库安装的 Electron。**Windows 真机和真实 GitHub 账号/网络尚未验收**；
HTTP 身份/私有性/权限检查使用合成响应，实际 Git 链路使用隔离本地远端，不将两者混称为真实 GitHub 成功。
