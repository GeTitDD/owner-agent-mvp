# 本地实际操作体验评估 · 2026-11-26

## 结论

当前版本能完成多项目排序、记灵感、灵感提升经验、候选入库和手动记录决策，数据链已经具有可用基础。但主路径仍要求用户记住命令、理解内部状态和绕过入口缺口。下一轮优先建设「第一次成功使用」与「回来就能继续」，再扩张能力。

最关键的五项：补齐添加项目与首次启动入口、隔离会话草稿、让定位屏直达待处理内容、让变化与决策真正解释项目现状、让审核卡展示完整入库内容。

## 环境与方法

- 版本：`feat/card-shell`，`65cdbae`；本次没有修改产品运行时代码。
- 环境：macOS arm64、Node.js 22.23.3、Electron 45.2.3；产品文档主要面向 Windows，本报告不能代替 Windows 验收。
- 部署：执行 `npm ci --no-audit --no-fund`，安装 517 个包，启动真实 Electron 主进程、真实渲染界面及 SQLite；另启动本机 Workbench，读取同一份隔离演示数据库。
- 操作：通过项目已有的 CDP 连接入口操作真实 Electron 窗口；点击使用鼠标事件、输入使用键盘事件与文本输入，截图来自真实渲染窗口。使用只读 DOM 检查补充截图。没有以静态 HTML 原型替代应用。
- 空数据完成首次使用评估后，使用存储 API 登记三个合成演示仓库，并准备一条经验候选；这是因为桌面卡片没有项目添加入口。此步骤不计为用户可自行完成的正常流程。数据注入后重载渲染器，以排除旧项目列表缓存对后续体验的影响。
- 灵感、灵感提升、候选生成、接受、手写决策、变化查看和标记已读均通过真实 UI 执行；没有启用假聊天回复。
- 本机探测未发现模型环境变量；首次使用模型目录使用隔离空目录。普通提问验证了缺模型的错误路径，未评估真实模型的回答质量、长回答流式效果、停止与引导。
- 未向飞书发送消息、未 Push 或创建 PR、未扫描个人真实 Agent 会话。Docker daemon 未运行，未评估补丁与沙箱旧链路。

## 必须优先修复

### UX-01 · P0：第一次添加项目没有可见路径

**复现**：全新数据库启动 → 点击「项目」→ 只有「全局」。空态要求「先登记一个项目」，但空态和下拉均无添加按钮。设置窗口同样没有添加入口。

**影响**：目标用户需要离开应用查文档或运行 CLI，才能开始使用。单窗口存在不等于旅程闭合。

**建议**：在空态提供主按钮「添加第一个项目」，项目下拉底部保留「＋添加项目」；调用已有目录选择能力即可，不增加第二套项目模型。首次进入自动创建会话，或让发送动作按需建会话。

**验收**：空库启动后不查文档、不用终端，可以选择本地仓库并到达项目概览；无须先理解会话概念。

证据：[首次启动](assets/2026-11-26-ux/01-first-launch.png)、[空项目下拉](assets/2026-11-26-ux/02-empty-project-picker.png)。已有桥接：`desktop/preload.cjs` 的 `settings.addProject`，主进程也已有目录选择逻辑。

### UX-02 · P0：未发送草稿跨项目串入新会话

**复现**：在「知识笔记（演示）」输入「这是知识笔记项目的未发送草稿，请不要发到别的项目。」→ 点击项目下拉 → 选「电商后台（演示）」→ 选择「新开会话并切换」。

**实际**：新项目的新会话保留旧草稿，发送按钮可用。此次没有发送该草稿。

**影响**：用户已经明确选择新会话，仍可能把项目 A 的内容发到项目 B。上下文归属是这个产品最需要可信的部分。

**建议**：草稿按 sessionId 隔离并持久化；切换后显示目标会话自己的草稿。只有显式「把草稿带过去」才迁移，并明确展示目标项目；取消切换恢复原状。

**验收**：A 写草稿 → 新开 B，B 输入框为空；返回 A 草稿原样恢复；重启后仍在；同会话跨项目时给出明确携带选项。

证据：[项目已切到电商后台，输入框仍是知识笔记的草稿](assets/2026-11-26-ux/22-draft-cross-project-leak.png)。

### UX-03 · P0：定位屏的待确认角标不能直达待确认内容

**复现**：定位屏「电商后台」显示「待确认 1（知识 1）」→ 点项目名 → 选择新开会话。

**实际**：只显示「这个会话还没有消息，发第一句开始」。需要额外知道并输入 `/经验`，才能看到那条候选；角标自身不可点。

**建议**：项目名恢复该项目上次会话；「待确认 N」直接在流内展示对应候选，「未读 N」直接展开变化。项目初次进入给一张紧凑的恢复上下文卡，不另做任务看板。

**验收**：从定位屏点击待确认角标，一次操作看到对应候选、完整内容及处理按钮；不需要输入命令。处理后计数同步下降。

证据：[定位屏](assets/2026-11-26-ux/09-locate-three-projects.png)、[点入后空会话](assets/2026-11-26-ux/11-project-entry-pending-invisible.png)。

### UX-04 · P0：数量和问题描述没有回答「上次到哪、为什么」

**复现 A**：`/变化` 显示「自上次看过：1 处变化」「新提交 1 条」，没有提交标题、作者、涉及文件或查看入口；同时水位已推进。

**复现 B**：手动决策中，现象为「多项目切换后需要重新翻聊天记录才能找到上次进度」，选择为「项目进入后先显示上次进度、未读变化和待确认决策」。返回定位屏，「最近决策」显示的是现象。

**影响**：知道有变化仍要另开 Git 工具；看到的「决策」不能说明究竟决定了什么。清零未读并不代表恢复了上下文。

**建议**：变化至少展示提交标题、时间、涉及文件与只读 diff 入口；最近决策以选择为主句，理由与来源可展开。摘要仍允许确定性生成，缺信息时明确说明，不需要依赖 LLM 编进度。水位在内容展示成功后才推进；「标记已读」保留独立显式操作。

**验收**：只用应用就能说出一条具体变化和最近一次选择及理由，并能追到原始证据。

证据：[变化只有计数](assets/2026-11-26-ux/20-changes-view.png)、[最近决策显示现象](assets/2026-11-26-ux/24-locate-after-saving-decision.png)。

### UX-05 · P0：审核时无法看清将写入的正文和证据

**复现**：`/经验` 打开存储层正常生成的知识候选，「主张」为「（无）」；通过真实 UI 从灵感提升为经验，再提升候选，卡片只显示标题、来源、状态和接受/拒绝，没有完整正文、证据、范围或改写入口。

**影响**：系统要求人确认，却没有提供完成判断所需的信息。经验卡的机制/对策可以为空，后续也没有就地补齐的明显路径。

**建议**：审核卡展示实际入库正文、项目/领域范围、来源与证据摘录；支持改写后接受；明确「推断」「未验证」的含义。创建候选和接受使用同一份视图模型，避免不同入口展示不同字段。

**验收**：正文与证据可展开查看，卡上预览与落库内容一致；范围明确可选；已接受的经验再次查询显示已有知识状态，避免重复诱导提升。

证据：[主张为空](assets/2026-11-26-ux/12-lessons-and-candidates.png)、[真实 UI 生成的候选缺正文与证据](assets/2026-11-26-ux/15-promote-candidate-empty-claim.png)。接线位置：`desktop/shell-compose.cjs:294` 附近。

### UX-06 · P0：登记项目会改动被观察仓库

**复现**：准备三个干净演示 Git 仓库 → 调用现有 `OwnerStore.registerProject` → 三个仓库均出现 `?? .owner-root-identity`。

**说明**：这一步是存储 API 的可复现实验，非卡片 UI 点击。它验证了未来接回「添加项目」按钮后会触发的现有行为。

**影响**：「只读、非侵入」是产品承诺，却在登记时写入项目目录。仓库自身的 `.gitignore` 只能让本项目忽略它，不能保护用户登记的其他仓库。

**建议**：目录身份记录保存在应用自有数据目录，通过规范路径和目录身份信息检测漂移；不向被观察仓库写标记，也不修改其 `.gitignore`。

**验收**：登记、查看、聊天、变化检查、监控后，目标仓库的文件和 Git 状态完全不变；覆盖可写与只读目录。

证据：[三个仓库登记前后 Git 状态](assets/2026-11-26-ux/registration-side-effects.json)。实现：`src/owner-store.mjs:489`，写标记在 500–503 行。

## 下一优先级

### UX-07 · P1：普通项目切换成本过高

一次普通切换弹四段后果、三种按钮，还把「在本会话切换」设为主操作，要求用户理解历史归属、读取来源、写入落点、跨项目标。

建议默认恢复目标项目自己的会话；「携带当前上下文到其他项目」另作显式高级动作。普通查看不做风险确认，真正有副作用时才确认。需同步调整已有 ADR，不应只删弹窗而保留不清晰的状态模型。

验收：普通项目切换一次点击完成、能回到原会话；读写范围清晰；不会混入历史、草稿或关联资料。

证据：[正常项目切换对话框](assets/2026-11-26-ux/21-normal-project-switch-dialog.png)。

### UX-08 · P1：命令发现不完整，缺失技能抢占注意力

`/` 面板的内置命令不包含需要参数的 `/记灵感`，但它恰好是经验链起点。面板还显示两个 `/0` 插件项、大量缺失 pstack 技能及「由面板按钮直接生成」的旧说明；对应旧面板已被移除。`/帮助`被当作普通模型问题，没有本地帮助。

建议把常用产品动作排在前面，含参数的命令选中后填入模板并定位光标；内置 `/帮助`；缺失技能默认折叠到可选安装区，修正 `/0` 显示名；不可用条目不与可用能力混排。保留完整命令索引供熟练用户使用。

验收：新用户不读文档可从面板发现并完成记灵感；命令帮助不依赖模型；默认列表没有无意义或失效条目。

证据：[命令面板](assets/2026-11-26-ux/07-slash-discovery.png)。

### UX-09 · P1：设置缺少接通模型的短路径，错误缺少恢复动作

设置一次展示七区大量信息。首屏同时出现主模型、图谱模型、网关及目录。主模型占位说「留空 = Pi 默认模型」，实际未配置时对话要求先选模型；错误消息只有文字，不能直接配置并重试。

建议新手只完成「添加项目 → 选择/连接模型 → 测试连接 → 第一问」，高级设置渐进展开；本地命令仍可在无模型时工作。错误卡提供「配置模型」「重试这一问」并保留原问题。不要把图谱、网关、令牌和技能目录作为首用前置知识。

验收：用户能在应用内理解缺少哪个前提并恢复；配置成功后不重输问题就能重试；空模型行为文案与运行逻辑一致。

证据：[无模型回复](assets/2026-11-26-ux/03-no-model-first-question.png)、[设置首屏](assets/2026-11-26-ux/04-config-first-screen.png)。

### UX-10 · P1：低风险回执太重，内部术语替代了结果

记一句灵感，回复先显示一段 UUID，再显示整张包含 `ideas 表`、放行判定、两次 UUID、ISO 时间的回执；提升动作又生成新的「我」与「Companion」消息。经验状态直接显示 `inferred`，按钮混用 Lesson，回顾时操作日志挤占正文。

建议默认只显示「已记到电商后台：<摘要>」和「整理成经验」；审计详情折叠保留。用中文状态与本地时间；原卡就地更新状态，审计事实继续完整保存。按钮清楚说明将存下什么，而不是要求用户先理解存储层级。

验收：单次记灵感的回执约 2–3 行，主结果与后续操作在同屏可见；展开才显示 id、路径、判定与精确时间。

证据：[灵感回执](assets/2026-11-26-ux/13-idea-receipt.png)。

### UX-11 · P1：固定窄窗与信息层级不匹配

主窗固定 440×640，不能拉伸。三张项目卡加说明已占满主要区域；项目名较长时被截断，候选与表单需要频繁滚动。同步未配置却常驻整行「从未成功同步过 / 补同步」，导出也始终占一行。

建议保留紧凑默认尺寸，但支持拖拽调整和宽屏展开；同步未配置只显示轻量「本机保存」状态，配置后再显示同步；导出移到会话操作；定位屏说明默认折叠成一句，避免与对话争同一滚动区域。不要用新增装饰弥补信息优先级问题。

验收：长项目名、长候选和四字段表单可清楚阅读；常用动作无需横向滚动；未启用同步时无故障式状态噪音。

证据：[三项目定位屏](assets/2026-11-26-ux/09-locate-three-projects.png)。窗口设置：`desktop/main.cjs:2657`。

### UX-12 · P1：工作台入口与语义割裂

完整工作台入口只在托盘；本机运行着 OpenClaw 时，现有 `openFull` 实际优先打开它，而非项目经验工作台。本轮为检查经验页，通过调试入口打开完整窗口，再导航到显式启动的本地 Workbench。Workbench 首页显示 v0.5、任务管理和其他旧概念，卡片壳当前方向却是不做任务看板。经验页用项目 ID 而非中文名，证据是引用字符串，缺少可点击返回来源的位置。

建议卡片提供明确的「查看全部经验」入口，带当前 projectId 直达经验页；本地经验工作台与 OpenClaw 分开命名；统一当前产品术语与版本；项目显示名称，来源具备可读标题和实际跳转。保留「卡片做流内查看与确认，工作台做系统浏览」的边界。

验收：从当前项目一次点击进入其经验列表，返回仍在原会话；连接 OpenClaw 与否不改变「查看经验」的落点；证据能返回真实来源或明确说明只能显示摘录。

证据：[工作台经验页](assets/2026-11-26-ux/25-workbench-lessons.png)。路由选择：`desktop/main.cjs:2704`。

## 已有优点，建议保留

- 待确认优先的定位排序容易理解；真正需要补的是内容入口与恢复上下文。
- 单项目「标记已读」不会清掉其他项目未读，实际验证成立；[操作结果](assets/2026-11-26-ux/26-mark-read-single-project.png)。
- `@@` 四种方法的动作说明比较直接，可以延续这种表达方式。
- 入库、取消和失败都有明确反馈；优化的是默认信息密度，不是删除审计证据。
- Workbench 能展示机制、对策与来源摘录，为卡片审核补全信息提供了现成数据基础。

## 建议实施顺序
