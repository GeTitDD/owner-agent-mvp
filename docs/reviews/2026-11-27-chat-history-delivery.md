# 长会话的读取、恢复与完整导出

日期：2026-11-27。持续目标仍为「使用体验流畅、已约定功能完整」；本报告只记录第四批的验收范围。

## 用户旅程

打开超过 500 条消息的会话，先看到最新回复；向上阅读时按需加载更早内容；读取失败时原地重试；
切换会话时保持各自的草稿和历史；原问题不在当前页中也能准确重试；导出和项目目录同步取完整正文。

空会话和短会话不显示无效分页；分页显示加载状态并阻止重复点击；失败有明确中文说明和重试；
到达开头后显示完成提示；生成模型回答时暂时禁用历史重画；切会话后的迟到请求直接丢弃。

## 已修复

1. `ChatSessionStore.getSession` 原来按 `seq ASC LIMIT 500` 读取最早 500 条。隔离测试写入 520 条，
   实际最后一条是「消息 499」，期望「消息 519」。现在从最新消息反向取一页，返回时恢复正序；
   `beforeSeq` 使用稳定序号，翻页期间新增消息不会造成偏移。
2. 界面首次加载最近 100 条，顶部提供「加载更早消息」。前插按可见消息序号恢复屏幕位置；
   同会话刷新保留已展开的范围，撤回能同步移除末轮，后台刷新不会把另一会话的结果混进来。
   勾选消息按稳定序号迁移，前插历史后不会把引用错指到别的消息。
3. 重试原问题改为按会话和消息序号精确读取；不再要求原问题出现在当前页中。
   保存重试结果后先标记已处理，再统一刷新，减少重复读取。
4. 完整导出在主进程读取存储正文，忽略界面加载窗口；项目同步同样显式读取完整正文。
   同步的会话、项目和标题在开始时固定，读取期间切换项目也不会改变原请求的目的地。
   勾选引用、复制单条消息等局部操作继续使用用户实际选中的内容。
5. 异步卡片动作保存最初的会话与消息，分页前插不再影响卡片回答归属。
6. 视觉检查发现导出提示曾挡住恢复按钮，已改为不接收点击；分页失败改为简洁中文，
   底层错误保留在悬停提示中；切会话清除原导出路径，异步导出完成也不回填到别的会话。

没有增加消息删除、自动压缩或后台会话扫描。模型输入的最近上下文策略没有因此扩大。

## 实际验收

命令：`npm run e2e:desktop:chat-history`。

真实 Electron、真实 preload/IPC 和 SQLite，起始 521 条消息。模型使用既有假流；临时宿主只对历史读取
注入一次失败与可控延迟，正常路径仍调用实际 handler。没有读取个人凭据，没有调用付费模型。

60 项断言通过，包含：首屏最新回复、未展开也完整导出、重复导出逐字节一致、跨页原问题重试、
草稿保持、失败重试、加载禁用态、滚动位置稳定、迟到请求隔离、键盘加载、引用勾选保持、
全部历史不重不漏、新消息不收起旧历史、撤回、同步完整性与确认门槛、重启恢复。
