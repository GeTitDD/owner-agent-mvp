# 从 GitHub 添加项目

范围已由用户在本对话确认并要求实施：保留本机目录入口，新增粘贴 GitHub 仓库链接；已添加则打开，已下载则核对并关联，否则选择新目录下载后进入项目。

成功旅程：从首次使用或项目菜单打开 GitHub 添加表单 → 填写链接 → 检查已有项目 → 打开已有项目，或选择本机仓库关联，或确认下载位置 → 成功后直接进入项目并可输入。

验收条件：
- 链接校验、检查中、下载进度、完成登记、成功、失败、取消均有明确反馈；失败保留输入，可直接重试。
- 地址和本机目录分开显示；本机目录必须与所填仓库匹配，不改原有 origin，不把不同目录的工作状态或经验静默合并。
- 新下载只进入明确选择的新目录；不覆盖已有目录，取消和失败不生成空项目，清理限于本次创建的下载临时目录。
- 下载不执行项目安装、构建、测试、子模块脚本，也不推送仓库；关联和登记不触发记忆同步。
- 长中文、较小窗口、深色、键盘操作及原会话草稿保留均实际操作并检查截图。
- 使用已有 Git/GitHub 凭据，表单不接收 token；仓库列表与新的账号登录界面不在首版。

本批采用隔离数据库和真实本机 Git 仓库验证，自动化不联系真实 GitHub、不调用模型。传输替代仅限测试宿主，实际 UI、IPC、Git 操作、项目登记与恢复走真实实现。

参考：现有 `src/github.mjs` 的仓库来源识别、项目登记及目录身份保护；GitHub CLI 的 `gh repo clone` / `gh auth git-credential` 与 Git clone 官方文档用于核对传输、进度及既有凭据的行为。
