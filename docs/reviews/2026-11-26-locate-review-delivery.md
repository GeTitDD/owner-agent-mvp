# 体验优先第二批：定位直达、具体变化与审核内容

日期：2026-11-26。分支 `feat/ux-first-use`，基线 `65cdbae`。本地开发记录，尚未提交或发布。

## 用户现在可以完成的旅程

1. 全局定位屏点击项目名，恢复这个项目最近的独立会话；跨项目视图与已删除会话不参与恢复。
2. 点击「待确认」，直接看到已有知识候选和决策候选，不必记命令，也不会扫描新会话。
3. 审核前看清实际入库正文、范围、适用与例外、证据摘录、引用、来源及验证状态。
4. 接受或拒绝；临时失败时动作仍可重试。同会话内重复出现的同一候选卡会同步收起操作。
5. 审核中切去另一个项目，结果仍写回原会话；返回全局时更新关注计数，原草稿保持隔离。
6. 点击「未读」，查看具体提交标题、作者、时间、文件与事件；只推进当前项目的水位。
7. `/经验` 中新提升的候选也使用同一份完整审核视图，重启后可继续处理。

## 修复的根因

- 待审接口原来返回所有项目的候选，且读取不存在的 `payload.claim`；现按项目归属先过滤再分页，正文取实际存储的 `payload.content`。
- 新增 `src/knowledge/candidate-view.mjs`，归属规则由定位计数、待审列表、经验提升回执共用；共享候选沿来源经验归属，不随意归给某项目。
- 定位计数沿候选引用读取来源经验，不再受最近 1000 条经验的截断影响。
- 变化原有数据包含条目，回复却只显示数量；现保留具体内容。没有水位或时间不明的历史另列为「无法判断新旧」，不当成新增或零条。
- 最近决策原来只显示现象；现显示实际选择，并附理由。
- 审核结果冻结原会话；失败不写入已回答标记，避免按钮永久消失。
- 多张完整候选按会话块大小分条保存，正文不截断。较长的证据/补充信息明确标为节选并提示回查来源，不冒充完整原始证据。

## 实际视觉检查与修复

macOS arm64、Node.js 22.23.3、Electron 45.2.3，真实 440×640 卡片。通过 CDP 鼠标和输入事件操作真实界面、IPC 和 SQLite；没有使用静态原型。

截图检查与操作中发现并修复：

- 中文文件名被 Git 转成八进制转义码：改为 NUL 分隔读取，同时保留带空格/换行的路径，重命名只算一个文件，旧路径单独显示。
- 审核卡复制按钮盖住状态徽章：为复制按钮预留位置，卡片正文与操作增加与标题一致的内边距。
- 多行输入时技能面板盖住「发送」：按真实输入区及关联胶囊高度定位，保留发送按钮可点击。
- 已结束的读取仍显示「正在读取」：完成时撤下本次加载提示，后出现的其他回执不被误清。
- 定位打开长内容时停在底部：现在先展示本次回复开头。

## 验证

- `npm test`：1249 项，1244 通过、5 跳过、0 失败。
- `npm run check`：277 个文件通过。
- `e2e:desktop:locate-review`：72 项断言通过，12 张截图，含重启。
- `e2e:desktop:first-use`：85 项断言通过，验证首次使用、添加、草稿隔离及延迟回复保护。
- 桌面壳、项目切换、技能、配置箱与关联菜单的回归记录见同目录 `verification.json`。
- 关联项目旧验收把渲染后 `textContent` 当作原始 Markdown 检查，导致标题/列表标记断言失败。本次改为检查实际持久化消息，同时另外检查渲染出的标题和列表；没有改动 prompt 的业务生成逻辑。

临时宿主只替代一次审核失败、一次读取失败和一次延迟；成功审核、拒绝、计数、水位和持久化均走真实实现。模型设置为假模型且本旅程未请求模型；扫描入口被测试宿主拦截并记录，验证没有调用。

正常启动器已重新启动桌面和本地工作台，保留三个演示项目。直接点击真实预览中的待确认也能打开完整候选，检查后已返回全局；未接受或拒绝演示候选。工作台首页与 `/lessons` 均返回 HTTP 200。

## 尚未覆盖与后续

- Windows 真机与打包未验收；没有评估真实模型质量、飞书投递或云同步。
- 这轮实现审核前看清范围，尚未增加知识候选的范围选择/内容改写；决策保留原有改写功能。
- 变化沿用现有最近 50 条提交/事件的探针边界和检查时推进水位语义。大仓库的完整分页、会话保存失败后的水位延迟确认仍需后续改进。
- 同一会话的重复卡已同步；其他会话历史中旧卡的后台状态刷新仍待完善，存储层仍拒绝重复审核。
- 普通项目下拉的四条后果确认仍保留；本轮仅简化定位屏的明确查看动作。
- 全部范围继续登记在 [持续迭代账本](experience-iteration-plan.md)，本次不宣称整体目标完成。
