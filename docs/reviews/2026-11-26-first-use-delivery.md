# 体验优先第一批：首次使用与草稿归属

日期：2026-11-26。基线：`65cdbae`；工作分支：`feat/ux-first-use`。这是本地开发交付记录，尚未发布。

## 本次用户旅程

1. 打开空数据的卡片即可输入，不必先学习新建会话。
2. 点击「添加第一个项目」选择目录；成功后直接进入项目，取消或失败保留原会话和输入。
3. 从「项目 → 添加项目」继续登记；重复选同一目录复用项目，不重复登记。
4. 输入多行中文草稿，切换会话或项目，再切回来与重启，正文和技能仍在各自的范围内。
5. 发出消息后清除已发送草稿；等待回复时可以编辑下一句，迟到回复不会清空新输入。
6. A 会话回复期间切到 B，B 的草稿不被作为 A 的引导发送；原回复也不会写入 B 会话。

本地演示已重启到当前工作分支，保留三个原有演示项目及会话；工作台接口 HTTP 200。[原生预览截图](assets/2026-11-26-first-use/12-live-preview.png)来自正常启动器，没有测试宿主替代。

## 已实现

### 首次使用

- 空项目界面提供主按钮和只读承诺，收起没有内容可排序时的排序规则说明。
- 首启自动准备会话；首次选项目时可复用没有消息、输入、置顶或自定义标题的全局空会话，避免制造多条空会话。
- 项目下拉增加添加入口，并在打开时重新读取项目列表。
- 添加过程中防止重复点击；目录不存在或无权限时给出中文恢复提示，保留当前输入。
- 新建会话沿用当前项目范围。

### 草稿与回复

- 草稿在应用 SQLite 中按「会话 ID＋视图项目」隔离保存，正文保留原始换行和空白，技能胶囊随草稿恢复。
- 切换先等待原草稿保存，再恢复目标范围；读取失败不以空白覆盖旧草稿。
- 关联项目资料和会话指针不自动跨范围携带。本次未实现关联资料的完整草稿恢复。
- 发送完成使用正文与技能的条件匹配清除草稿，保留等待期间的新版本。
- 等待回复期间允许编辑下一句；跨会话引导被明确拦下，草稿保留。
- 模型请求使用发起时冻结的会话和项目，切换后不向其他项目渲染原轮次的增量。

### 非侵入登记

- 新项目读取目录身份并写入应用数据库，不创建 `.owner-root-identity`，不改项目 `.gitignore`。
- 保留目录替换检测；旧项目仍只读校验历史标记，不擅自删除或重写它。
- 自动化覆盖干净 Git 仓库登记前后状态一致、普通编辑不误判、替换目录拒绝及旧标记兼容。

### 开发原则

`AGENTS.md` 指向 `CONTRIBUTING.md` 的「体验优先与视觉验收」，PR 模板要求提供用户旅程、真实截图、平台与未覆盖项。交付以用户任务成功和视觉验收为准，测试通过是必要条件之一。

## 实际视觉验收

环境：macOS arm64、Node.js 22.23.3、Electron 45.2.3；窗口保持产品原来的 440×640。

通过真实 Electron 的鼠标、文本和键盘事件操作，截图直接来自渲染窗口。目录选择器只在临时测试宿主中替代，界面、主进程 IPC、项目登记及 SQLite 都走真实代码；没有向生产代码加入选择器测试开关。普通问答使用显式假模型，延迟回复也在测试宿主中注入，不调用付费模型。

本次打开并检查了浅色、深色、长项目名、多行中文、成功、取消、失败、重启和跨项目回复状态的截图。视觉检查发现并修正：

1. 成功通知遮挡多行输入框：改为随输入区与草稿状态的布局变化定位在其上方，并增加不遮挡断言。
2. 错误文字在项目浮层溢出：改为中文恢复提示、正常换行，并增加文本宽度断言；默认不展示 IPC 名称。
3. 深色主按钮沿用已有前景色令牌，保证按钮文字可读。
4. 项目下拉中的长中文名允许换行；其他会话回复时，新项目显示「等待」并保留可编辑草稿，隐藏不适用的引导动作。
