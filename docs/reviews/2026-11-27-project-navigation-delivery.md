# 项目上下文恢复与同步反馈

日期：2026-11-27。第五批迭代，整体目标继续进行中。

## 用户旅程与结果

从项目菜单选择另一个项目，直接继续其最近的独立会话，恢复历史与草稿；返回原项目时，原输入仍在。
不再为了普通导航先读四条后果、再选择新会话或跨项目。当前已经是目标项目的独立会话时保持原位；
没有可恢复会话才创建，置顶顺序、跨项目视图和已删除记录不会代替最近的独立上下文。

「在本会话查看」是明确的次要动作：仍显示四条后果，确认后才更改原会话的视图范围，
历史绑定不变，保留跨项目标记和原有写入审批。取消不改变范围或草稿。

读取期间显示「正在打开…」并阻止重复点击；会话列表失败在菜单中给重试提示。
目标历史加载失败时回到原会话和草稿，避免顶栏、正文、输入框分属不同项目。
慢导航不会覆盖后来显式选择的会话。项目进出不推进未读水位、不扫描个人会话、不改项目仓库。

## 同步能力的实际边界

本次核对正常主进程时，发现 `runSyncAttempt` 的非验收路径始终返回 `unconfigured`：
同步计划和冲突执行规则已有，真实远端传输与目标配置尚未接入。此前显示「补同步」会反复得到这个结果，
旧文案还暗示配置箱接入后即可使用，与当前实际能力不符。

现在正常宿主显示「仅本机 / 跨设备同步尚未接入」，「了解同步」直接打开真实能力说明，
不会调用无效的同步尝试。运行时能力与历史状态分开传递，即使磁盘有以前的验收成功记录，
也不会把当前未接入的执行器显示为绿色「已同步」。README 同步说明也已校正。

状态读取本身失败时，顶栏显示「状态未知 / 重试读取」，不再把错误藏在关闭的会话菜单里。
对已接入执行器的反馈规则，用仓库已有的显式假执行器验证：失败显示可执行的中文提示，
保留最后成功时间，原始步骤和错误留在悬停详情；恢复后才显示成功。摘要可换行，避免下一步被省略号截掉。

**这不是已实现真实跨设备同步的声明。** 真正的远端适配器、目标配置、文档清单与冲突确认接入仍是功能缺口。
