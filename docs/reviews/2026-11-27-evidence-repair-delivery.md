## 已修复的行为

### 复现按独立事实证据计算

`PersonalKnowledgeStore` 将来源台账与独立执行支持分开：灵感、未知类型的文字引用不充当执行事实；同一执行记录或引用跨项目重复出现，不作为多个独立来源。
不同项目的独立执行证据仍可以支持「同一现象已复现」，但不证明机制或对策有效，不改变项目/领域范围，也不自动标为已验证。

历史记录和同步导入携带的 `reproduced` 等字段不再直接决定徽章，读取时根据当前证据重新计算。
因此旧误标不需要用户逐条重建；不因一次阅读而批量重写原始正文、验证状态或证据。
归档与已被取代的记录不提供当前事实支持，显式升域也不会把来源项目数当作验证结论。
重复合并灵感来源仍保持推断，不再因「证据行非空」升为待验证。

来源台账继续保留全部出处；`supportProjects` / `supportedByProjects` 只表示当前独立执行支持。
旧分类缺失、或只有远端来源台账而本机没有相应事实证据时保守不打标，不自动补造事实。

### 完成对话引用与任务复用分开计量

新增的完成对话引用记录，只保存本轮、会话、查看项目、来源条目身份/修订和上下文摘要哈希，不复制知识正文。
只有成功完成且确实提供了资料的对话才记入；按轮次及条目修订去重，重载或重复保存不增加次数。
只检索、容量不足未注入、模型失败、取消均不计入这一保守口径。

引用记录与任务 Usage、收益反馈使用不同记录，不混入知识自动升级依据。
工作台分别显示「已完成对话引用」和「任务上下文复用」，任务结果与复用收益分别标注；任务成功、收益未知可以同时成立。
桌面成功回执明确说明提供资料不等于模型采纳或收益；计量保存失败时保留回答并提示未保存，不把回答改成模型失败。
工作台读取结果还会核对当前选中条目，防止迟到结果写入另一条知识的详情。

### 视觉验收中追加修复的发送与取消问题

实际按钮旅程暴露三个此前单元测试遗漏的边界，均先补了可失败的回归再修复：

1. 发送上下文附加的 `linkedProjects` 导致整对象草稿比较永不相等，原问题留在输入框；点停止会把它当成流式插入草稿，甚至自动重发。比较现已限定为会话、项目、正文、技能四项；发送后清空原文，后来输入或其他会话的草稿不被清掉。
2. SDK 的 `abort()` 可能先让 prompt 正常结束，抢在取消 Promise 前完成。现在显式停止信号优先，准备阶段已停止时不创建会话/发出 prompt；主进程先登记可取消轮次，再等待服务初始化，避免准备阶段找不到轮次。
3. SDK 可能在整条消息完成前不更新最终正文，停止后把已经显示的文字误作「没有产出」。现在按本轮保留已转发的正文，引导新回答时清空旧缓冲，停止时优先保留实际流出的文字。

真实界面已验证：发送后原问题清空；有实际流式内容时停止保留文字并显示已停止；取消不增加完成对话引用。

## 文档与存储分歧的处理

保留 ADR-0002 的历史背景，增加明确的当前实现说明，区分「本机采用什么表示读写」与「跨设备冲突谁优先」。
已核对现有 issue #103、#130，它们明确文档同步与冲突交人，但未完整决定本机表示分工。
[ADR-0016](../adr/0016-local-memory-representation.md) 是 **proposed 草案**，比较继续使用本机 SQLite 事务/修订与恢复 Markdown 权威表示的取舍，尚未宣告为已接受决定。

本轮没有迁移既有记忆内容、改动同步冲突政策或替用户向远端 issue 发布决定。
架构方向仍须按贡献指南完成 issue 讨论；业务缺陷修复不依赖先做存储迁移。
