# 真实同步接入的实现与验收清单

目标不变：从桌面设置私有同步仓库，检查清单与冲突，确认后完成同步；失败可恢复，另一份应用存储可实际使用收到的记忆。
本清单是持续迭代的工程记录，不替代整体目标，也不是已交付声明。

## 已核实的现状

- 实施前正常主进程的同步执行器返回 unconfigured；本轮已连接 MemorySyncController 的预览/确认通道，旧 attempt 接口不能绕过确认。
- `sync-plan.mjs` 与 `sync-run.mjs` 已有文档计划、先拉后推与冲突四选一规则，但没有真实传输依赖。
- 活跃知识、决策和经验在 `PersonalKnowledgeStore` 的 SQLite 中；不能只同步新建空目录或导出的聊天，便宣称应用记忆已同步。
- Markdown 是传输投影，收到后通过现有存储的校验与修订机制应用，不新增一份可独立修改的本机事实源。

## 执行顺序

1. 传输与严格文档编码，并用两个隔离本地 Git 克隆证明读写与并发保护。
2. 连接实际知识存储与完整枚举，形成可预览、可应用、可恢复的同步服务。
3. 设置、桌面清单与冲突选择入口，复用现有单窗口对话流与状态反馈。
4. 完整旅程、视觉验收、正常预览与文档，按本清单审计剩余缺口。

## 实施后的边界

- 活跃知识、决策与经验及证据已进入真实同步，不同步画像、图谱、快照、域定义和执行审计。
- 项目 ID 保留并提示本机未登记情况；不会猜测目录。跨机器项目绑定引导仍是后续项。
- 基线损坏会明确停止，避免把旧设备当新设备；自动恢复/迁移引导未提供。
- 合并后正文超过存储限制时停止并提示，不截断；可重新检查选择某一侧或跳过。
- 机器路径仅处理结构化字段；正文与选定证据摘录仍由用户在完整预览中核对。
- 真实 GitHub 私有性、身份与写权限检验已接入固定官方接口；该 HTTP 层测试注入合成响应，未对个人账号发起请求。
