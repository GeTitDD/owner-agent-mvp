# 体验优先第三批：模型接入与失败恢复

日期：2026-11-27（本轮开发始于 11 月 26 日，跨日完成验收）。工作分支 `feat/ux-first-use`，基线 `65cdbae`；本地改动，尚未提交或发布。

## 本次用户旅程

未配置模型时提问 → 回复下方直接打开模型设置 → 从模型目录选择并保存 → 重试原问题。

鉴权失败后可以重开应用继续恢复；重试不重复添加用户问题，不覆盖后来写下的草稿。
重试中切到其他项目，原回答继续写回原会话，新项目可编辑草稿并明确显示「等待」。
保存新模型从下一问生效，不中断正在进行的旧模型回答。未知模型在请求前被拒绝，不静默改用默认服务。

## 真实发现与修复

### 模型实际绑定错误

原来的 `resolvePiModel` 会把 `provider/model` 字符串，或目录里缺少 provider/API 的原始模型记录交给 SDK。
真实 SDK 的隔离回归测试得到 `undefined/undefined`；旧的假 SDK 测试没有覆盖这个契约。

修复后通过 SDK 的 `ModelRuntime` 解析完整模型，并把解析用的同一个运行时交给会话。
对话、默认 Pi 会话、Playbook 只读会话及 Writer 创建点统一接入；不加载项目扩展或放开工具权限。
目录和请求共用相同的 Pi 目录选择规则，支持 `PI_CODING_AGENT_DIR`；验收使用独立的测试目录。
打开设置不请求远端模型目录刷新，模型与凭据解析仍由安装的 SDK 负责。

回归经历：`node --test tests/pi-model-selection.test.mjs` 先复现失败，再验证模型身份正确。
随后加入真实 SDK 经本机 HTTP/SSE 的成功和 401 分支，验证不只是元数据看起来正确。

### 失败后的恢复

- 在失败回复下增加「模型设置 / 重试原问题 / 取回问题」；超长问题只提供编辑恢复，只读校验失败不提供继续请求的按钮。
- 恢复卡只保存原用户消息序号、项目及技能指针，不复制另一份问题正文。
- 重试直接读取原问题，保留原技能与关联资料；不走命令分派，不重复追加用户消息，不清当前草稿。
- 失败以 `status=error` 入库，避免错误提示进入模型的正常续聊上下文。重试以原问题序号截取此前上下文，不混入后来的消息。
- 部分回答明确标成「未完成」；保存新模型保留正在回答的会话，结束后再释放。

### 配置与视觉

- 修正「主模型留空 = Pi 默认模型」的错误提示，改为「暂不连接模型」。
- 配置页区分未选择、目录未知、未检测到凭据、已检测到凭据；明确本地检测不等于网络、额度和凭据有效性已验证。
- 模型目录由真实 SDK 生成；发往界面的数据只包含 ID、名称、提供商、来源及状态，不包含 API key、地址或鉴权头。
- 增加「刷新模型目录」，保留配置草稿；支持按名称、提供商与 ID 搜索，先过滤后展示最多 100 个匹配项，并保留当前选择。模型选择器的宽度跟随容器，长模型 ID 不再撑出窗口。
- 关闭配置箱时撤下它自己的保存通知，避免通知继续遮挡对话流内的恢复按钮；不会误清后来出现的其他提示。

## 实际验收

环境：macOS arm64、Node.js 22.23.3、Electron 45.2.3、Pi SDK 1.5.0。使用真实 Electron、真实 IPC、SQLite、安装的 SDK 和本机 HTTP/SSE 服务。
没有替代聊天 IPC，没有使用 `OWNER_AGENT_CHAT_FAKE`，没有请求付费模型服务或使用个人凭据。
仅模型服务返回的是可控夹具：成功、401、延迟流式回复。
