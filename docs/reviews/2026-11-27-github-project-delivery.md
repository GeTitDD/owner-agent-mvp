# 从 GitHub 添加项目交付

日期：2026-11-27。范围对应 [本批计划](2026-11-27-github-project-plan.md) 与用户确认的第一版：粘贴链接、打开已登记项目、关联已有目录、下载后进入项目。

## 可以直接使用的入口

首次使用页和顶栏「项目」菜单都增加了「从 GitHub 添加」，保留本机目录入口。

1. 粘贴仓库主页链接、SSH 地址或 `用户名/仓库名`，检查格式和本机已登记项目。
2. 已登记且目录可读取时直接打开已有项目，恢复其独立会话，不重复下载或合并不同工作副本的记忆。
3. 已下载但未登记时选择本机仓库根目录；origin 与所填来源一致才关联，不改动原有远端。
4. 本机没有时选择保存位置和新文件夹名称，确认「下载并添加」，成功后直接进入项目并可输入。

检查链接阶段只校验仓库身份与本机匹配，不宣称已经验证远端访问权限；实际下载才验证网络与访问能力。
项目菜单分别显示本机路径与 GitHub 来源，仓库链接可直接打开；读取这些来源只读本机 origin，不因打开菜单发起 GitHub 网络查询。

## 输入、下载与取消

- 格式、目录不匹配、同名目录、权限和网络错误都在原位说明，保留链接、保存位置与文件夹名称；原会话草稿与添加表单分别保留。
- 新下载先进入本次创建的临时目录；成功后原子预留新的目标目录，再放入下载内容并登记。目标已存在或操作期间出现同名目录时停止，不覆盖原目录。
- 下载不运行安装、构建、测试或项目脚本，不递归拉取子模块，禁用此次 Git 操作的钩子；不提交、推送或设置记忆同步。
- Git 通过独立参数启动，表单不接收 token；沿用本机既有 Git/GitHub 凭据。进度仅传阶段与百分比，不将任意远端输出或凭据回传界面。
- 主进程记录原生目录选择的用途与目录身份。不能仅凭渲染进程传入路径任意关联或下载；目录变化后要求重新选择。
- 采用上一批取消链路的经验：先登记请求，再进行异步准备；刚点击下载就取消也不会漏掉。下载中取消会等待子进程退出与临时目录清理，完成登记阶段不再中断。
- 正常退出应用时先取消或完成正在进行的添加，等待清理后再关闭数据库。不会将未完成的下载注册成项目。
